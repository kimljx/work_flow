Linux 服务器现场部署步骤

适用场景
1. 目标机器是可直接登录操作的 Linux x86_64 服务器。
2. 服务器上已有 Tomcat，但本系统不部署进 Tomcat。
3. 本系统独立监听 18849 端口。

一、准备工作
1. 确认已经拿到 Linux 离线包。
   文件名示例：
   work_flow_linux_offline_py310_YYYYMMDD_HHMMSS.tar.gz
2. 确认服务器具备以下基础命令：
   tar
   bash
   ss
   systemctl
   curl
3. 以有写权限的账号登录服务器。

二、部署前检查
1. 检查系统架构
   uname -m
   预期结果：
   x86_64
2. 检查 18849 端口是否被占用
   ss -ltnp | grep 18849
   如果有输出，先处理端口冲突。
3. 建议确认部署目录
   mkdir -p /opt/work_flow_release
4. 如果服务器启用了防火墙，需要提前放行 18849。
   firewalld 示例：
   firewall-cmd --permanent --add-port=18849/tcp
   firewall-cmd --reload

三、上传并解压
1. 上传离线包到服务器，例如上传到 /opt
2. 解压
   cd /opt
   tar -xzf work_flow_linux_offline_py310_YYYYMMDD_HHMMSS.tar.gz
3. 规范目录名
   mv work_flow_linux_offline_py310_YYYYMMDD_HHMMSS /opt/work_flow_release
4. 进入目录
   cd /opt/work_flow_release

四、首次检查
1. 执行离线安装检查
   ./install_offline.sh
2. 如果报错，优先看这些方向：
   包是否完整
   是否缺少 Linux 系统库
   config/ 下证书是否为空文件
   runtime/ms-playwright/ 是否存在

五、配置应用
1. 编辑环境变量文件
   vi app/.env
2. 至少确认这些项：
   QAX_BASE_URL
   QAX_USERNAME
   QAX_PASSWORD
   SMTP_HOST
   SMTP_PORT
   SMTP_USER
   SMTP_PASSWORD
   SMTP_FROM_ADDRESS
   IMAP_HOST 或 POP3_HOST
3. 如果使用浏览器证书登录，把证书放到：
   config/
4. 如果目标站点要求客户端证书，优先准备：
   .p12
   .pfx

六、启动并验证
1. 启动服务
   ./start_system.sh
2. 查看启动日志
   tail -n 200 local/logs/server.log
3. 验证本机访问
   curl http://127.0.0.1:18849/
4. 如果只是确认端口已监听，也可以执行：
   ss -ltnp | grep 18849

七、配置 systemd 开机自启
1. 复制 service 模板
   cp service/work_flow.service /etc/systemd/system/work_flow.service
2. 如果你的部署目录不是 /opt/work_flow_release，先编辑 service 文件：
   vi /etc/systemd/system/work_flow.service
3. 需要按实际情况修改这些路径：
   WorkingDirectory
   ExecStart
   ExecStop
   PIDFile
4. 重新加载 systemd
   systemctl daemon-reload
5. 设置开机自启
   systemctl enable work_flow
6. 启动服务
   systemctl start work_flow
7. 查看状态
   systemctl status work_flow
8. 查看日志
   journalctl -u work_flow -n 200 --no-pager

八、与 Tomcat 共存
1. Tomcat 可以继续跑原来的业务。
2. 本系统不需要放进 Tomcat。
3. 如果需要统一入口，建议由 Nginx 或现有反向代理转发：
   127.0.0.1:18849
4. 如果以后要做域名访问，也建议走反向代理，不建议直接暴露 uvicorn。

九、常见故障排查
1. 启动脚本执行失败
   先看：
   tail -n 200 local/logs/server.log
2. systemd 启动失败
   看：
   systemctl status work_flow
   journalctl -u work_flow -n 200 --no-pager
3. QAX 登录失败
   检查：
   config/ 下证书是否为空
   是否只有 .cer 而没有 .p12/.pfx
   服务器系统信任链是否已导入
4. Playwright 启动失败
   大概率是 Linux 系统库缺失，需由运维补齐浏览器依赖库。

十、升级建议
1. 升级前先备份
   ./backup_data.sh
2. 再执行升级
   ./upgrade_from_release.sh <新版本目录>
3. 升级后复核：
   app/.env
   config/ 证书文件
   local/logs/server.log
