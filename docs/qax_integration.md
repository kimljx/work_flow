# QAX 集成说明

- QAX 只属于通知域，不直接修改任务主状态。
- 发送模块职责：
  - 登录
  - 导航到目标页面
  - 按用户 IP 筛选
  - 创建即时消息任务
  - 使用“通知 ID + 接收人 ID + 通知类型 + 任务标题”生成唯一任务名，便于后续按任务名回查
- 采集模块职责：
  - 按任务名查询送达/已读状态
  - 将结果写回通知相关数据表
- QAX 状态映射规则已固定为两段语义：`row_text` 中的“准备中 / 执行中 / 执行结束 / 已取消”表示 QAX 任务是否已发出，`detail_text` 中的“未接收 / 正在执行 / 执行成功 / 执行失败”表示终端用户是否接收或确认；其中“执行成功”按本系统“已读”处理。
- QAX 正文不会保留邮件专属的“回复指引”；如果管理员把邮件模板内容复制到 QAX 模板中，系统会在发送前自动剔除这些说明，避免即时消息里出现无法执行的回复动作。
- 当前提供 `POST /api/v1/admin/qax/collect` 手动触发一次状态采集，便于联调或排障时立即回写最新结果。
- 同时支持后台按 `QAX_COLLECT_CRON` 定时执行状态采集；当配置为空字符串时视为关闭自动采集。
- 手动采集与自动采集都会写入系统日志，模块名分别为 `api.qax` 和 `scheduler.qax`，便于系统管理员排查送达与已读回写情况。
- 运行前需要安装 `playwright` 依赖，并执行一次浏览器安装，例如 `playwright install chromium`。
- 当前启用的配置项包括：
  - `QAX_BASE_URL`
  - `QAX_USERNAME`
  - `QAX_PASSWORD`
  - `QAX_GROUP_NAME`
  - `QAX_COLLECT_CRON`
  - `QAX_BROWSER_HEADLESS`
  - `QAX_IGNORE_HTTPS_ERRORS`
- 即使后续替换运行时驱动，只要保持接口契约一致，前后端逻辑无需变化。
